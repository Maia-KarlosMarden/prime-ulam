# Abstract

We present Prime-Ulam LDPC, a family of binary erasure codes whose parity-check structure is generated by a formula from a prime $p$ and a small set of integers. No parity-check matrix is stored: besides $p$, the description consists of 34 integers and a 32-row table giving, for each data arm, the families it belongs to. The construction combines three elements derived from the same modular plane: sparse equations placed along families of modular spirals, which contain no length-4 cycles by a short arithmetic argument; a parity chain with accumulator structure, closed into a cycle; and sixteen dense equations defined by the norm of Gaussian integers modulo $p$ together with a quadratic-residue test. At rate 0.80, with 1,480 transmitted symbols, the code shows no decoding failures in 150,000 random erasure patterns at 17.5% loss, and a failure rate of $1.3\times10^{-4}$ at 19% loss, against $1.9\times10^{-3}$ for the 5G NR LDPC base graphs at the same rate and length. Decoding uses only XOR operations on packets and runs at 2.5 to 3.7 GB/s for loss rates up to 15% in a plain C implementation on a virtual machine. We state the limits plainly: RaptorQ and Reed–Solomon recover every pattern up to the information-theoretic limit, which the binary sparse codes here do not, and our measurements cover the erasure channel only.


# 1. Introduction

Erasure coding protects data that arrives incomplete rather than corrupted: a dropped network packet, a failed disk sector, or a satellite link that loses line of sight for a few milliseconds. The receiver knows which symbols are missing but not their content. A systematic erasure code adds $m$ parity symbols to $k$ data symbols, and its rate is $R = k/(k+m)$.

Low-density parity-check (LDPC) codes [Gallager 1962] are a standard choice when the parity-check matrix is sparse and well designed. Their performance depends strongly on short cycles in the Tanner graph. Two data symbols that share two parity equations form a cycle of length four, and such cycles create linear dependencies that prevent recovery. Designing a sparse matrix is therefore largely a matter of avoiding these cycles. General-purpose methods such as progressive edge growth (PEG) [Hu, Eleftheriou, Arnold 2005] do this by search.

This paper describes a different route. The starting point was a geometric observation about the Ulam spiral, in which the integers are written along a spiral and primes line up along diagonals and arms. The question was whether this geometry could decide which data symbols enter which parity equation. The answer is more specific: what matters is not the position of primes on the spiral but the prime as the modulus of the arithmetic that defines the connections. When the modulus is prime, the absence of length-4 cycles in the sparse part follows from a short argument rather than from a search.

The paper makes four claims, each supported in Sections 4 and 5:

1. A rate-0.80 erasure code can be specified by a prime, a small set of integers and one incidence table, with no parity-check matrix stored.
2. Its sparse part has no length-4 cycles, by a short theorem.
3. With a dense precode built from Gaussian-integer norms, it outperforms the 5G NR LDPC base graphs at the same rate and block length in the moderate-loss regime, under a common set of erasure patterns.
4. Its decoder uses only XOR on packets and reaches high throughput when loss is at most about 15%.

We do not claim novelty for each individual ingredient. Section 6 lists the literature each ingredient descends from.

# 2. Background and notation

Let $\mathrm{GF}(2)$ be the binary field. A parity-check matrix $H$ has one row per parity equation and one column per code symbol. On the erasure channel, with a set $E$ of erased positions, the unknowns are recovered if and only if the columns of $H$ indexed by $E$ are linearly independent over $\mathrm{GF}(2)$. Two decoders are used:

- **Peeling**: while some equation contains exactly one unknown, solve it, substitute, and repeat. This needs no matrix operations and is the cheapest decoder.
- **Gaussian elimination (rank decoding)** on the residual system left when peeling stops. This is maximum-likelihood for the erasure pattern and is the reference used here.

A **length-4 cycle** corresponds to two columns of the sparse part that share two rows. A **dense** equation contains a constant fraction of all data symbols; a **sparse** equation contains a bounded number.

# 3. Construction

## 3.1 Parameters and block structure

The construction is defined for a prime $p > 32$. For $p = 37$ the block has $n = 1{,}480$ transmitted symbols; for $p = 127$, $n = 5{,}080$. The same parameter set, with a different prime, defines the family. There are $A = 32$ arms and $MB = 10$ spiral families, with $M = 10p$ parity symbols.

| Element | Definition | Count |
|---|---|---|
| Data symbols | 32 arms $\times$ $p$ radial positions | $k = 32p$ |
| Untransmitted arms | arms 12 and 23 (degree 8); their data are never sent and are recovered as unknowns | $2p$ data symbols |
| Spiral families | 10 families, each with step $s_c$ | 10 |
| Sparse equations | one per value of $(j + s_c i) \bmod p$, per family | $10p$ |
| Parity symbols | accumulator chain, closed into a cycle | $10p$ |
| Parity symbols replaced | 16 sparse parities are not sent; dense parities take their slots | 16 |
| Dense equations | Gaussian-norm test with centers in arithmetic progression | 16 |
| Transmitted total | $30p$ data $+ (10p - 16)$ sparse parities $+ 16$ dense parities | $n = 40p$ |
| Rate | $k/n$ | $0.80$ |

## 3.2 Sparse part and the no-$C_4$ theorem

Arm $i$ participates in a subset $F_i$ of the ten families, given by the incidence table in Appendix A. Arms 12 and 23 belong to eight families each, and the other thirty arms to three each. Each family receives 10 or 11 arms. A data symbol at position $(i, j)$, with arm $i$ and radius $j$, enters, for each family $c \in F_i$, the sparse equation

$$
q(i,j,c) = 10\cdot\Big(\big(a_c\cdot\big((j + s_c\, i) \bmod p\big) + b_c\big) \bmod p\Big) + c,
$$

where $s_c$ is the step of family $c$ and $(a_c, b_c)$ place its equations in the index range $\{0,\dots,10p-1\}$. Within a family, the equation depends only on the value $(j + s_c i) \bmod p$.

**Claim.** Let $p$ be prime and let $c \neq c'$ be two families with $s_c \not\equiv s_{c'} \pmod p$. Then no two distinct data symbols share an equation of family $c$ and an equation of family $c'$. Consequently the sparse part contains no length-4 cycle.

*Argument.* A data symbol has exactly one sparse equation in each family it belongs to. So two equations shared by two distinct data symbols must come from two distinct families $c \neq c'$. Suppose $(i,j)$ and $(i',j')$ share an equation of family $c$ and one of family $c'$. Then $j + s_c i \equiv j' + s_c i'$ and $j + s_{c'} i \equiv j' + s_{c'} i' \pmod p$. Subtracting gives $(s_c - s_{c'})(i - i') \equiv 0 \pmod p$. Since $p$ is prime and $s_c \not\equiv s_{c'}$, we get $i \equiv i'$, and then $j \equiv j'$. The two symbols coincide, contradicting their distinctness. $\square$

This converts the spiral picture into a theorem. The argument needs $p$ prime: it uses that $s_c - s_{c'}$ is invertible modulo $p$. The script in Section 10 checks the sparse part of the released codes directly: zero pairs of data symbols share two sparse equations, for $p = 37$ and $p = 127$. It also tests the role of the modulus on a grid of $m$ arms and $m$ radii, with the same steps reduced modulo $m$: for $m = 17$ there are no length-4 cycles, while for $m = 16$ there are 3,584 pairs of data symbols sharing two equations.

## 3.3 Accumulator chain

Parity $q$ enters equations $q-1$ and $q$, for $q \ge 1$. Parity 0 enters equations $0$, $M/2$ and $M-1$, which closes the chain into a cycle. Every parity is protected by two equations, and encoding remains sequential along the chain. This is the accumulator form of repeat-accumulate and IRA codes [Jin, Khandekar, McEliece 2000], with the chain closed to remove the free end.

## 3.4 Dense precode

Sixteen dense equations $k = 0,\dots,15$ are added, each with its own dense parity symbol. Dense equation $k$ has center

$$
(a_k, b_k) = \big((5k) \bmod p,\ (7k + 1) \bmod p\big),
$$

and contains data symbol $(i, j)$ when

$$
\big((i - a_k)^2 + (j - b_k)^2\big) \bmod p \ \in\ \{x^2 \bmod p : 1 \le x < p\}.
$$

The quantity inside the test is the norm of the Gaussian integer $(i - a_k) + (j - b_k)\,\mathrm{I}$ modulo $p$, where $\mathrm{I}$ is the imaginary unit. The test is a quadratic-residue (Paley-type) condition on that norm. Each dense equation contains roughly half of the data symbols. In the transmitted code, sixteen dense parities occupy the transmission slots of sixteen sparse parities, namely the parities with indices $K + \lfloor qM/16 \rfloor + \lfloor M/32 \rfloor$ for $q = 0,\dots,15$, which are not sent.

The motivation was geometric: treating each spiral point as a Gaussian integer and multiplying by the conjugate gives a real number, which suggested the norm as a connection rule. We know of no reference using this combination for an erasure precode. A formal prior-art search has not been performed, so this is stated as "not found in the sources consulted", not as a proven fact.

## 3.5 Transmission order

Symbols are sent in a fixed pattern of four slots: three data slots, then one parity slot, repeated. Since $M/n = 1/4$, the parity slots are exactly every fourth slot. For data slot number $t$ the transmitted arm is $\tau_{t \bmod 30}$, where $\tau_0 < \tau_1 < \dots < \tau_{29}$ are the 30 transmitted arms in increasing order, and the radius is $(g\,t) \bmod p$. For parity slot number $q$ the transmitted symbol is parity $(h\,q) \bmod M$. The integers $g$ and $h$ are chosen to maximize the length of a cyclic burst that is always recoverable: $g = 20$, $h = 61$ for $p = 37$, and $g = 14$, $h = 829$ for $p = 127$.

## 3.6 Decoding

The decoder first peels the sparse equations. When peeling stalls, the remaining unknowns form a small system, solved by Gaussian elimination over $\mathrm{GF}(2)$ together with the dense equations. All operations are XORs of packets. The decoder reads the exported code file, which lists for each variable the equations it belongs to.

## 3.7 Size of the description

The construction is specified by: the prime $p$; ten steps $s_c$; ten coefficients $a_c$ and ten coefficients $b_c$; the two untransmitted arms; the two integers $g$ and $h$. Together with $p$ this is 35 numbers in all, 34 of them besides $p$. The incidence table $F_i$ for the 32 arms adds 106 memberships in total. The sixteen dense centers are given by the formula in Section 3.4, and the parity chain is fixed by its definition. No parity-check matrix is stored. The incidence table is the one non-formula ingredient: it was produced by a seeded search in the construction script and is recorded as data. Its size is small, but the construction should not be called "table-free" without this qualification.

# 4. Results

All results come from simulation on the binary erasure channel. Decoding success is exact, by rank over $\mathrm{GF}(2)$. The same erasure patterns are applied to every code in a comparison, and all codes have rate 0.80. "Failure" means at least one data symbol could not be reconstructed. The corresponding raw outputs are in `results/` in the repository, named in each subsection.

## 4.1 Comparison with the 5G NR LDPC

The 5G comparison uses the base graphs BG1 and BG2 from 3GPP TS 38.212, lifted to the block length and rate of the Prime-Ulam code. The base-graph tables were extracted from the NVIDIA Sionna 2.2.0 package. The assembled matrices were checked against the Sionna `LDPC5GEncoder` on six $(K, n)$ configurations, with matching outputs (`src/benchmarks/validate5g.py`).

The table below is taken from `results/fair37.log` (1,480 symbols, 150,000 patterns) and `results/fair127.log` (5,080 symbols, 15,000 patterns). "v5+G" is the final code.

| Block | Loss | Patterns | Prime-Ulam v5+G | 5G NR (BG1) |
|---|---|---|---|---|
| 1,480 | 17.5% | 150,000 | 0 failures | 10 failures ($6.7\times10^{-5}$) |
| 1,480 | 19.0% | 150,000 | 19 failures ($1.3\times10^{-4}$) | 285 failures ($1.9\times10^{-3}$) |
| 1,480 | 19.5% | 150,000 | 3,531 failures (2.4%) | 15,989 failures (10.7%) |
| 5,080 | 17.5% | 15,000 | 0 failures | 0 failures |
| 5,080 | 19.0% | 15,000 | 0 failures | 0 failures |
| 5,080 | 19.5% | 15,000 | 0 failures | 9 failures ($6.0\times10^{-4}$) |

The information-theoretic loss limit at rate 0.80 is 20%. At 19% loss with 1,480 symbols the Prime-Ulam code fails about fifteen times less often than 5G NR; at 19.5%, about four and a half times less often. These are point estimates from the stated sample sizes. For $0$ failures in 150,000 patterns, the 95% upper bound on the failure rate is roughly $2\times10^{-5}$; failure rates below that were not measured.

## 4.2 Error floor and the role of the dense precode

The version without the dense precode (v5 alone) has a residual floor. With 400,000 patterns (`results/floor_37_*.json`, `results/fl37b_0.log`), its failure rate is $1.4\times10^{-4}$ at 15%, $3.8\times10^{-4}$ at 16.5% and $5.0\times10^{-4}$ at 17.5%, with Wilson 95% intervals in the logs. In the rate-matched comparison at 17.5% (`results/fair37.log`, 150,000 patterns), v5 alone fails 80 times and v5+G fails 0 times. The floor is consistent with low-weight codewords built from degree-3 data symbols; we did not isolate every such codeword.

The dense precode is therefore responsible for removing the floor in this experiment. Whether its geometric centers are better than random dense equations is not established by our data. For the sixteen-equation case, `results/gd37.log` (100,000 patterns at 19% and 19.5%) shows zero failures for three variants: centers chosen at random, the diagonal centers $(5k, 7k+1)$ used in the final code, and random dense equations. At this sample size the variants are indistinguishable. An earlier comparison with eight equations, in which random dense equations failed six times, is described in our working notes but its log is not in the repository, so we do not rely on it here.

## 4.3 Burst recovery

Burst comparisons used the same transmission-order search for all codes, with two interleaver types (G1: single-step, G2: two-stream), as in `src/benchmarks/burst_eq.py`. The logs are `results/be37.log` and `results/be127.log`. The value reported is the longest cyclic burst that was always recovered in the measured sample of starting positions.

For 1,480 symbols (theoretical limit 296): Prime-Ulam 288, 5G NR (BG1) 287, PEG with accumulator 282. For 5,080 symbols (limit 1,016): Prime-Ulam 1,009, 5G NR 1,007, PEG 980. The stored order used in the main results gives 285 for Prime-Ulam at 1,480 symbols and 1,006 at 5,080 symbols.

These differences are of one or two symbols for the two good codes. The burst guarantee is therefore a property of the interleaver, which good codes can all receive, and it does not separate the codes. The PEG code is clearly lower under the same search.

## 4.4 Decoding cost

A plain C decoder without explicit SIMD, using 1 KB symbols, on a virtual machine with a Xeon at 2.1 GHz and two vCPUs, was measured with `src/decoder/pudec.c` (usage in Section 10). The raw XOR throughput of the machine on 1 KB packets is 11.0 GB/s (`src/decoder/xorbw.c`).

| Loss | 1,480 symbols (1.2 MB) | 5,080 symbols (4.2 MB) | XORs per data symbol |
|---|---|---|---|
| 10% | 0.33 ms (3.7 GB/s) | 1.5 ms (2.8 GB/s) | 4.7 |
| 15% | 0.46 ms (2.6 GB/s) | 1.7 ms (2.5 GB/s) | 5.2 to 5.6 |
| 17% | 0.99 ms (1.2 GB/s) | 5.4 ms (0.77 GB/s) | 15 to 19 |
| 19% | 1.43 ms (0.85 GB/s) | 13.4 ms (0.31 GB/s) | 28 to 55 |

Below about 15% loss, peeling resolves almost all unknowns with about five XORs per data symbol. Near the limit, Gaussian elimination dominates and the cost rises by roughly an order of magnitude. The absolute times depend on the machine; ratios between codes measured on the same machine are the meaningful quantity.

## 4.5 Scaling

For 5,080 symbols the final code shows no failures at 17.5%, 19% and 19.5% in 15,000 patterns, as shown in Section 4.1. Generating a code for another block size requires choosing another prime, but we have built and measured only $p = 37$ and $p = 127$ for the final construction.

# 5. Comparison with established codes

Four references were measured under the same protocol: the 5G NR LDPC, PEG (a regular sparse design with a stored matrix), Reed–Solomon over GF(256), and RaptorQ (RFC 6330, via the Rust implementation `raptorq` 2.0.0 with its Python binding). Native RaptorQ throughput figures are those published by the library authors for a different machine and are used only as an external reference. Our Python measurements of RaptorQ are not comparable to the native C decoder.

| Criterion | Prime-Ulam v5+G | 5G NR LDPC | PEG regular | Reed–Solomon | RaptorQ |
|---|---|---|---|---|---|
| Failure at 19% (1,480 symbols) | $1.3\times10^{-4}$ | $1.9\times10^{-3}$ | $5.7\times10^{-2}$ | none (optimal) | about 0 (about 1/256 per symbol of overhead) |
| Recovery at exact limit (20%) | fails | fails | fails | 100% | 99.5% |
| Decoding at 15% loss | 2.5 to 3.7 GB/s, XOR only | similar, XOR only | similar | GF(256) arithmetic, slower | about 1 GB/s native (published) |
| Code description | one prime, 34 integers and one 32-row table | standardized tables | stored matrix | one generator polynomial | tables and a pseudo-random generator |
| Block sizes | $40p$, $p$ prime | 51 lifting sizes, two base graphs | any | up to 255 symbols over GF(256) | any $k$ |
| Rate | fixed 0.80 (generalization open) | adjustable by puncturing | fixed | adjustable | rateless |
| Length-4 cycles | none, by theorem (sparse part) | none, by design | none, by algorithm | not applicable | not applicable |
| Patents or licensing | none known for the constructions | 3GPP standard, essential patents | none known | none known | Qualcomm patents involved |

**Scientific reading.** For pure recovery, Reed–Solomon and RaptorQ are optimal or nearly optimal. Binary sparse LDPC codes, including Prime-Ulam and 5G NR, do not reach the information-theoretic limit in our measurements. Within the class of binary LDPC codes, Prime-Ulam v5+G is the best of the three we measured, with a margin of about four to fifteen times over 5G NR near the limit, depending on the loss rate.

**Commercial reading.** The code with the lowest failure rate is not necessarily the most adopted. The 5G NR LDPC code is widely deployed because it was standardized, has dedicated hardware, is designed for the noisy channel where it is actually used, and guarantees interoperability. RaptorQ is common in file delivery and streaming because it is rateless and has a recovery guarantee. Reed–Solomon is common in storage because it is optimal and long established. Prime-Ulam does not match any of these on their home ground. Its case rests on the combination of properties in the table above.

**Trade-offs.** Prime-Ulam beats 5G NR in recovery and in the compactness of its description, and loses to it in ecosystem, hardware availability, and rate flexibility. It is faster than RaptorQ at low loss and free of known licensing, and loses in recovery guarantee, rate flexibility, and speed near the limit. It is faster than Reed–Solomon in decoding cost and in block-size flexibility, and loses in recovery guarantee.

# 6. Relation to prior work

Each ingredient has a precedent in the literature.

| Ingredient | Closest precedent | What is added here |
|---|---|---|
| Spiral-based sparse graphs free of $C_4$ | Array codes [Fan 2000]; finite-geometry LDPC codes [Kou, Lin, Fossorier 2001] | Derivation from prime-modulus lines; integration with the other parts |
| Accumulator parity | IRA codes [Jin, Khandekar, McEliece 2000] | Closed chain; positions given by an affine formula |
| Irregular degrees and untransmitted bits | Irregular LDPC codes [Luby et al. 1998]; 5G NR | Irregularity per arm, with the incidence table recorded as data |
| Dense precode | HDPC component of RaptorQ [RFC 6330] | Dense equations from Gaussian-norm and quadratic-residue tests over GF(2), instead of GF(256) |
| Interleaver by formula | Quadratic permutation polynomial interleavers [3GPP TS 36.212] | Joint choice with the code geometry |

No single ingredient is new in this list. The contribution is the combination: one geometric object, the plane of integers modulo a prime viewed as a spiral, generates the sparse part, the parity chain positions, the dense equations and the transmission order. In existing codes these components come from different sources and are tuned separately. Here they are functions of the same prime, except for the incidence table, which is recorded as data.

The methodological path is also part of the work. The project began from a hypothesis about primes, tested it against random controls (a random regular graph with length-4 cycles removed by edge swaps performed as well as the optimized spiral families in early tests), identified the mechanism (the prime modulus), and rebuilt the code on it.

# 7. Application niches

The profile where Prime-Ulam is most likely to be useful is: predictable and moderate loss (up to about 15%), a modest processor, little memory for tables, block sizes outside standard sets, and a need for open specifications. Where loss approaches the limit or an absolute recovery guarantee is required, RaptorQ and Reed–Solomon remain the right choice.

- **Small satellites in low Earth orbit and ground–satellite links.** Modest on-board processors, a compact description, and moderate loss from blockage and scintillation. Incumbents are CCSDS codes and RaptorQ in DVB. The entry point is small university and commercial missions not bound to CCSDS.
- **Free-space optical and inter-satellite links.** Burst losses from turbulence, a transmission order specified by formula, and fast decoding at moderate loss. Incumbents are Reed–Solomon and DVB-S2 LDPC.
- **IoT and sensor networks.** Microcontrollers without finite-field multipliers can decode with XOR alone. For 1,480 symbols of 32 bytes at 15% loss, the decoder needs roughly 8,000 XORs of 32 bytes. By estimate this is on the order of a millisecond on a 32-bit microcontroller; we have not measured it on such hardware.
- **Distributed and edge storage on heterogeneous nodes.** Reconstruction by XOR is cheap on weak nodes, block sizes can be chosen through the prime, and there are no known licensing constraints.

These are assessments based on the measured properties, not field tests. None of these niches has been validated on hardware.

# 8. Limitations and future work

**Code.** Only rate 0.80 has been built and measured. The structure admits other rates with more families or arms, which was not carried out. Block lengths are discrete ($40p$), and intermediate lengths would require shortening, which was not tested. There is no absolute guarantee: at 19% loss with 1,480 symbols the failure rate is $1.3\times10^{-4}$. Above about 17% loss, Gaussian elimination dominates and decoding is several times slower. Only the erasure channel was measured; behaviour with belief-propagation decoding on a noisy channel, the main use of 5G NR, is unknown. The incidence table is found by search and has no closed-form derivation.

**Measurement.** Failure rates below about $10^{-5}$ were not measured. The C decoder is a direct implementation without SIMD or inactivation decoding. The burst values are measured on samples of starting positions, not on all of them. Coefficients, centers and the incidence table were selected by short searches; there is no proof that they are optimal.

**Future work, in order of value.** (1) A family of rates from 0.50 to 0.95 from the same formula, measured at each rate. (2) An inactivation decoder with SIMD to close the timing gap near the limit. (3) A formal proof of the minimum distance of the sparse part and of the effect of the Gaussian precode. (4) An FPGA implementation with energy-per-symbol measurement. (5) Comparison with the CCSDS standard and with local-repair codes used in storage.

# 10. Reproducibility

All experiments use Python 3 with NumPy and openpyxl for generation, and a C decoder compiled with `gcc -O3`. Random seeds are fixed in every script, and the same erasure patterns are applied to every code within a comparison. Success is full recovery of all symbols, verified by the rank of the erased submatrix over GF(2).

**Check of the formulas.** `src/verify/verify_article.py` reconstructs the final code from the formulas in Sections 3.2 to 3.5, using only the parameters in `src/construction/v5_p37.json` and `src/construction/v5_p127.json`, and compares it with the exported code `data/codes/code_p37.txt` and `data/codes/code_p127.txt`. For both primes, the script reports that every variable's equation set matches, the transmission order matches, the header and untransmitted list match, the rate is $0.80$, the sparse part has zero length-4 cycles, and the transmission pattern is three data slots followed by one parity slot. Running it from the repository root:

```
python3 -I src/verify/verify_article.py 37 127
```

# 11. Conclusion

A binary erasure code with rate 0.80 can be specified by a prime, 34 small integers and one incidence table, with no parity-check matrix stored, a sparse part without length-4 cycles by theorem, and a dense precode based on Gaussian-integer norms. In the moderate-loss regime it outperforms the 5G NR LDPC base graphs at equal rate and length, and its decoder is XOR-only and fast at low loss. It does not reach the recovery guarantee of RaptorQ or Reed–Solomon, and its measurements are limited to the erasure channel and to one rate. The contribution lies mainly in the compact, theorem-backed construction and its geometric derivation. We consider it a basis for further work on rate families, hardware, and noisy-channel performance.
